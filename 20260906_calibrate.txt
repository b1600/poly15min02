how to  save future dry-run outputs to text before they're overwritten so this comparison is possible next time

  Searched for 1 pattern

Simplest fix: pipe the command through tee instead of just eyeballing the terminal, using a filename that encodes both the date and that it's a dry run (so a same-day --write run doesn't clobber it):

.venv/bin/poly15m-calibrate | tee "$(date +%Y%m%d)_calibrate_dryrun.txt"

Review the table. If it looks good and you decide to persist it:

.venv/bin/poly15m-calibrate --write | tee "$(date +%Y%m%d)_calibrate_write.txt"

Two filenames per day (_dryrun vs _write) instead of one _calibrate.txt, 
so the pre-write table survives even when you write on the same day — 
that's exactly the gap that bit you on Sep 4: the dry run happened, 
but only the coefficients from the eventual --write landed anywhere durable (var/calibration.json), 
and the table itself was gone.

A couple of things worth doing on top of that, given this is git-tracked:

1. Commit each output right after saving it, before running anything else. 
Right now these .txt files sit uncommitted/modified for a while (as in today's git status) — 
if you re-run before committing, you're relying on not overwriting the same filename. 
A quick git add <file> && git commit -m "..." per run removes that risk entirely.
2. If you ever run calibrate twice in one day (e.g., re-running after fixing something), 
add a counter or time-of-day suffix ($(date +%Y%m%d_%H%M)) so the second run doesn't overwrite the first.

That's it — no code changes needed, just redirect with tee (so you still see it live) and commit before moving on.
